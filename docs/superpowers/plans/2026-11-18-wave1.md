## Global constraints (every stream)
- AGENTS.md rules apply: zero document retention (ADR-003/010), no network endpoints outside Groq / local Postgres / official PyPI+npm, `GROQ_MODEL` from the environment (never hard-code a model), no raw `print()`, naming conventions, docs-as-code gate, single API process (ADR-019), Alembic for any schema change.
- **No fabrication** (project principle): never claim something was measured or verified that was not. Evaluation numbers come only from the existing synthetic, labelled datasets and must be described as such (`docs/evaluation/phase4-harnesses.md`). Anything that could not be run here (Docker stack, device, GitHub CI) is stated as unverified.
- **No PHI in telemetry**: metric labels, log fields, trace attributes, cache keys and eval outputs never contain document text, patient identifiers, case ids (use the existing fingerprint helper) or free text from users.
- Streams do **not** edit `PROJECT_CONTEXT.md` or `CHANGELOG.md` (merge-conflict hotspots). Each stream writes `docs/superpowers/handoff/wave1-<stream>.md` (what shipped, decisions, env vars, follow-ups, unverified items); the integrator merges these into PROJECT_CONTEXT/CHANGELOG.
- Each stream defines its own settings class in its own module (pydantic `BaseSettings`, reading its own env vars) instead of editing `apps/api/app/config.py`.
- Test-first; run the project's checks before reporting (see each stream); report real output; commit in logical commits on the stream branch, each message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` for opus-run streams or `Claude Sonnet 5.5` for sonnet-run streams.
- Never leave dev servers or containers running.

## Interface between WS1 and WS2 (glue is done by the integrator)
- WS2 exposes in `packages/kadi/kadi/llm/observer.py`: `register_llm_observer(fn)` and the event type `LlmCallEvent(model: str, kind: str, outcome: str, latency_s: float, prompt_tokens: int | None, completion_tokens: int | None, cache_hit: bool, retries: int, circuit_state: str)` — no prompt text, no response text. `outcome` ∈ `ok | error | timeout | rate_limited | circuit_open | budget_exceeded | fallback`.
- WS1 exposes in `apps/api/app/telemetry/llm_metrics.py`: `record_llm_event(event: LlmCallEventLike) -> None` (duck-typed on the fields above, so WS1 does not import WS2 code) updating Prometheus counters/histograms with bounded label sets.
- After both merge, the integrator registers `record_llm_event` as an observer at API startup and adds one test. Until then each stream tests its side with fakes.

## Streams

### WS1 — Observability (branch `ws1/observability`)
Deliver, self-hosted only:
1. **Metrics:** Prometheus `/metrics` on the API (not exposed through the public API router: separate path guarded by an env flag `METRICS_ENABLED`, default true in dev, and documented as internal-only), HTTP latency/throughput/error metrics labelled by **route template** (reuse `route_template` in `observability.py`), pipeline stage durations, upload rejections, DB pool gauges if cheap, and the LLM metrics from the interface above. Keep the existing `LatencyTracker` and its endpoints working (compatible; may feed from the same measurements).
2. **Tracing:** OpenTelemetry (SDK + FastAPI/httpx/SQLAlchemy instrumentation where available) exporting OTLP to a collector; off by default (`OTEL_ENABLED=false`), no-op and import-safe when disabled; trace id added to the JSON log records beside `request_id`.
3. **Logs:** structured JSON logs already exist; add what is needed for shipping to Loki without mounting the Docker socket (prefer the OTel Collector / Loki push path; justify the choice in the design note).
4. **Stack:** `docker-compose.observability.yml` override (Prometheus, Grafana with provisioned datasources and dashboards as JSON, Loki, Tempo, OTel Collector, Alertmanager), everything bound to `127.0.0.1`, images pinned by tag (and digest if known), no anonymous Grafana access, admin password from env with a documented dev default that is refused in `APP_ENV=production`, healthchecks, named volumes, resource limits. Dashboards: API RED metrics, LLM calls (latency, errors, tokens, circuit state), case pipeline stages, SLO view. Alert rules with SLO burn-rate alerts (p95 case latency, 5xx rate, LLM error rate, circuit open) — validated with `promtool check rules` where runnable.
5. **Tests:** unit tests for metrics (label sets bounded, no case id/PHI in any label — a test that fuzzes with PHI-looking input), middleware behaviour, OTel-off no-op, trace-id in logs, `/metrics` gating; config validation tests (parse the compose file and the Prometheus/Alertmanager/Grafana YAML/JSON: services, ports bound to 127.0.0.1, pinned images, no docker.sock mount).
6. **Docs:** `docs/operations/observability.md`, ADR-023 (self-hosted telemetry, no outbound), env vars in `docs/configuration/environment-variables.md` + `.env.example`, new deps in `apps/api/requirements.txt`, troubleshooting entry.
7. **Docker:** pulling images and running the stack needs Docker running and network access to image registries, which is outside the AGENTS.md network rule; the user asked for the docker instances to be created, so write and validate the files (`docker compose -f docker-compose.yml -f docker-compose.observability.yml config`) but do NOT pull images or start containers in this stream; list the exact first-run commands in the docs and report "stack not started; images not pulled" as unverified.

### WS2 — LLM reliability (branch `ws2/llm-reliability`)
Extend (do not duplicate) the existing Phase-4 evaluation work. Deliver:
1. **Resilient client** in `packages/kadi/kadi/llm/`: one place that performs Groq chat calls with timeout, retries with jittered exponential backoff (429/5xx/timeouts), a **circuit breaker** (closed/open/half-open, injectable clock for tests), optional **fallback model** (`GROQ_FALLBACK_MODEL`, never a hard-coded or deprecated model), per-case **token budget** (`BudgetExceeded`), and an optional in-memory **response cache** keyed by a hash of (redacted input, model, prompt version) — **disabled by default**, bounded LRU + short TTL, never persisted, never keyed or valued on raw documents (zero retention); document the residual risk in ADR-024.
2. **Migrate the existing call sites** (`billnyay_llm.py` GroqClient, `kadi/extraction.py`, `billnyay/agents/barrister.py`, any other found by grep) to the resilient client **without changing their public behaviour** (they must keep their existing offline fallbacks); keep the model name coming from `GROQ_MODEL`.
3. **Observer hook** per the interface above (events carry no text).
4. **Prompt/model versioning + shadow runs**: a `PromptVersion` registry and an opt-in shadow runner that runs a candidate (model/prompt) next to production on the same redacted input and records only agreement metrics (no content) — off by default, bounded cost.
5. **CI evaluation gate (offline, deterministic)**: extend `apps/api/app/evaluation/` and `scripts/evaluate_phase4.py` with a regression gate comparing the harness metrics to a committed baseline file with tolerances; fails CI on regression. State plainly that it measures the offline paths on synthetic data (`docs/evaluation/phase4-harnesses.md`), not LLM accuracy. Add the CI step to `.github/workflows/ci.yml` as its own small job (append-only). An optional live-LLM eval may exist as a manual script gated on `GROQ_API_KEY`; it must never run in CI and never claim numbers without a run.
6. **Tests**: breaker state machine (fake clock), backoff schedule (seeded jitter), retry classification, budget enforcement, cache keying + zero-retention properties, fallback model selection, observer events contain no text (property-style test), migration of each call site keeps its fallback behaviour when the client fails.
7. **Docs:** ADR-024, `docs/evaluation/` update, env vars (`GROQ_FALLBACK_MODEL`, breaker/retry/budget/cache settings) in `docs/configuration/environment-variables.md` + `.env.example`, troubleshooting entry.

### WS4-shell — Web shell (branch `ws4/web-shell`, `apps/web` only)
The app frame every page lives in; page contents are redesigned later, one page at a time.
1. **Shell:** header (scroll-aware, language switcher, theme toggle, mobile navigation drawer), footer, module navigation, skip link, focus rings, safe-area handling, consistent page container and section primitives, route transitions via `navigateWithTransition`; installable PWA manifest (`manifest.webmanifest` + icons as SVG/maskable; **no service worker** — offline caching of documents would violate zero retention). Uses tokens and the motion system only (no new animation library).
2. **Performance (hard goal):** reduce initial JS per route from the KNOWN_VIOLATIONS ceilings toward the 170 KB budget — code-split heavy module views and below-the-fold landing sections (`next/dynamic`), remove unused client code from the shell, check `use client` boundaries; **ratchet `KNOWN_VIOLATIONS` down** to the new measured values (never up) and document the numbers.
3. **CLS fix (planned follow-up from WS0):** the font swap shifts `ul.lp-assurances`; fix it with `next/font/local` pointing at the already-installed `@fontsource-variable/*` woff2 files (no network) for the heading families and size-adjusted fallbacks (`adjustFontFallback`) feeding the token font stack, or an equivalent `size-adjust`/`ascent-override` CSS fallback; show lhci/PerformanceObserver CLS before/after; keep the 0.1 limit.
4. **Responsive + a11y:** verify at 375, 768 and 1280 px (Browser tools `resize_window`) and in dark/light; keyboard navigation; reduced motion; contrast of the shell; Hindi and Marathi text in the shell (Devanagari rendering).
5. **Tests/docs:** unit/source tests in the existing style (`apps/web/tests/`), `npm run lint`, `npm test`, `npm run build`, `check:web-budget`; docs for the shell components and the budget changes (web sections of `docs/development/performance-budgets.md`), handoff file. Take screenshots for the report.

### WS5-shell — Mobile shell (branch `ws5/mobile-shell`, `apps/mobile` only)
1. **Mobile web preview (so the app can be seen without a device):** add dev-only support to run the Expo app in the browser (`react-native-web`, `react-dom`, `@expo/metro-runtime` at the versions `npx expo install` picks for SDK 52; official npm only) with an npm script and docs; it is a **preview, not a device-faithful run** (haptics and some native behaviour differ) and must not change the native bundle. Use it with the Browser tools to look at the shell at phone width.
2. **Shell:** animated bottom tab bar, header, themed status bar, screen transition options, safe areas, loading skeleton and empty-state primitives, `Button`/`Card`/pressables moved onto the motion system's `Pressable`/`Reveal` (respecting the reduce-motion store), consistent spacing/typography from tokens.
3. **Fonts for real:** the loaded Expo font families are not applied anywhere and the generated `fonts` tokens are CSS stacks. Add a typography helper mapping weights to the real family names (`Inter_400Regular`, `Fraunces_*`, ...), use it in the shell, and fix the deferred items: `useAppFonts` timeout guard (never hold the splash forever), `Pressable` must not clobber a caller-supplied `transform`, late reduce-motion prime must not replay `Reveal`.
4. **Budget:** importing `src/motion` bundles Reanimated; re-measure with `npx expo export --platform android` (see `docs/development/performance-baseline.md`), stay within `MOBILE_BUNDLE_BUDGET_BYTES` (2,900,000), report the number and update the mobile sections of `docs/development/performance-budgets.md` only. Do not import `react-native-gesture-handler` unless a gesture is actually used (it cost ~934 KB).
5. **Tests/docs:** `npm run type-check`, `npm test` (existing style; pure logic in logic modules), `check:mobile-budget`; Browser screenshots of the shell via the web preview at 375x812 for the report; state plainly that nothing was run on a device. Handoff file.

## Review and integration
1. Each stream is reviewed by an independent reviewer (spec + quality + the global constraints above); Important/Critical findings go back to the stream's implementer; scoped re-review.
2. The integrator merges the stream branches into `wave1/integration` (order: WS2, WS1, WS4, WS5), resolves trivial conflicts, adds the WS1↔WS2 glue + test, merges the handoff notes into PROJECT_CONTEXT/CHANGELOG, runs the full checks, a whole-wave review, then opens one PR to `main`.
3. Anything the integrator rules on goes in the PR description under "Rulings".
