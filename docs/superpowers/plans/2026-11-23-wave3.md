# Wave 3 plan: product experience transformation (web and mobile)

**Status:** DRAFT v2 (2026-11-23). Milestone 1 (audit and architecture) is written; nothing else is started.
**Inputs:** the maintainer's "Master UI/UX transformation" brief (2026-11-23) and
`docs/design/wave3-ux-architecture.md`, which holds the audit, the information architecture, the screen inventory,
the backend gap report and the conflicts with project ground rules. Read that first.

## 1. Scope

Wave 3 turns the two-route web app and the seven-screen mobile app into the product the brief describes, **within
the project's ground rules**: no user accounts (ADR-008/009) unless decision D1 changes that; no document retention
(ADR-003); no fabricated figures, statuses or testimonials; no network calls outside Groq, Postgres and the package
registries.

**Not in scope:** account system (unless D1), push notifications, cross-case analytics, insurer submission, maps,
WS6 anomaly detection, the job queue (ADR-025), the Next.js upgrade.

## 4. Definition of done for a page

1. Every state exists: empty, loading, success, error, partial, insufficient evidence, and offline on mobile.
2. Every figure comes from an API response or is explicitly labelled as a synthetic example.
3. Evidence states use the single EvidenceBadge vocabulary.
4. Seen in a real browser at 1440, 1280, 1024, 768, 390 and 360 px, dark and light, en, hi and mr, keyboard only,
   reduced motion; screenshots attached.
5. No new accessibility violations; AA contrast.
6. Route bundle within its ceiling (or lowered); mobile within budget.
7. Lint, unit tests, build, `check:generated`, budgets and mobile type-check green, run and reported with output.
8. Maintainer sign-off, recorded in the milestone handoff file.

## 5. Verification honesty

Web is checked in the built-in browser. Mobile is checked only in the web preview, and the handoff says so. Hindi
and Marathi copy is a stub awaiting native-speaker review. Lighthouse numbers come from the CI job. Pre-existing
failures are reported separately from new ones.

## 6. Risks

| Risk | Mitigation |
|---|---|
| Scope (30+ screens) overruns the project timeline | Milestones are independently shippable; M3 and M4 alone give a demonstrable product |
| Rebrand breaks contrast in one theme | Token tests compute contrast for every text/background pair |
| Bundle growth from motion and charts | Public pages are Server Components; charts are plain SVG; ratchet only down |
| Pages imply data that does not exist | Inventory statuses are enforced; "Blocked" and "Not built" pages get no placeholder routes |
| Shared-file collisions between streams | One owner per shared file; primitives land in M2 before page streams |
