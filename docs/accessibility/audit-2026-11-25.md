# Accessibility audit, 2026-11-25

**Screen reader: NOT TESTED.** NVDA is not installed on the audit machine and no person listened to
any screen. Nothing here may be read as a screen-reader pass or as WCAG conformance. The checks
below are automated and scripted.

## Scope and method

Production build of the web app, local API on PostgreSQL with the synthetic demo account, Chrome
(headless), axe-core 4.14.0 with the `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` and
`best-practice` rules.

| Check | Coverage |
|---|---|
| axe-core | 28 routes (18 public including an unknown address, 10 signed-in including `/review`) × English, Hindi, Marathi × light, dark = 168 page loads at 1280 px |
| Horizontal overflow | The same routes × 3 languages × 360, 390, 768, 1024, 1280, 1440 px, plus 320 px (reflow, WCAG 1.4.10) |
| Keyboard walk | Every route at 1280 and 390 px, English light: tab order, visible focus, accessible text, focus on screen and not covered |
| Targeted walk | Skip link, announced sign-in error, tracker error, sign-out |

## Findings and fixes (first run → rerun)

| # | Rule / impact | Where | Fix |
|---|---|---|---|
| 1 | `label-content-name-mismatch`, serious | Header brand link | Removed the `aria-label` that dropped visible words |
| 2 | `color-contrast`, serious | Public pages: text faded in on scroll (as low as 1.1:1 while entering) | The reveal now moves without fading |
| 3 | `color-contrast`, serious | Settings "verify email" link, browser blue on dark (1.7:1) | Unstyled links use the text colour and an underline |
| 4 | `nested-interactive`, `label-content-name-mismatch`, serious | Upload drop zone was a button containing buttons | Drop zone is a plain drop target; "Browse" and "Camera" are the keyboard route |
| 5 | `label-content-name-mismatch`, serious | Case evidence graph: shortened node labels | Accessible name starts with the visible text |
| 6 | `scrollable-region-focusable`, serious | Document excerpt and draft letters | Focusable |
| 7 | `heading-order`, moderate | Reviewer sign-in | Added the missing level |
| 8 | Focus covered (WCAG 2.4.11), keyboard walk | Demo mode only: the fixed bottom banner hid focused controls on the case desk, reviewer page and footer | Scroll padding keeps focused controls above the banner |

**Rerun after fixes 1 to 7: 0 axe violations on all 168 page loads.** After the later changes (fix 8, the demo
account note), `/app`, `/app/case` and `/app/settings` were rerun (18 loads, 0 violations); the other
routes were not.

## Charts

Charts expose `role="img"` with a text summary and the same numbers as a data table. Their presence
passes axe; whether the summaries are useful when heard is untested.

## NVDA script for a person (about 30 minutes)

Chrome and current NVDA on Windows, demo account (docs/DEMO_GUIDE.md).

1. `/`: headings list (`NVDA+F7`), landmarks, language switch announces the new language.
2. Switch to हिंदी and मराठी: is Devanagari read with the right voice?
3. `/login`: field labels, password toggle, wrong password announced once.
4. `/app`: demo label, case list, upload without a mouse, progress announcements during processing.
5. A bill audit: result groups, counts, the chart summary and its data table, evidence badges.
6. Tracker: status change announced; the date error is announced and focus stays usable.
7. Delete a case: dialog name, focus trap, Escape, focus return.
8. Theme and reduced motion settings.

Record each step as pass, fail or blocked, with what was heard.
